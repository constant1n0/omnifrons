`omnifrons-domain` never depends on Tauri, Tokio, or any adapter — ADR-0002's requirement that "domain, handoff, event, scope, and recovery contracts must run and test without Tauri or a WebView" (adr/0002-desktop-technology-stack.md § Proposed decision) is a compile-time property of this dependency table, not a convention to remember. `omnifrons-app` shares that constraint: its `ProcessSupervisor` port (`crates/omnifrons-app/src/process_supervisor.rs`) is sync-with-deadline rather than `async fn`, precisely so this crate is never forced to depend on an async runtime; only `omnifrons-supervisor`, the adapter that actually needs one, depends on Tokio. `cargo tree -p omnifrons-domain` and `cargo tree -p omnifrons-app -e normal` are the standing checks for this property (see Build and test commands).

The root `Cargo.toml`'s `members` list now carries an explicit `"src-tauri"` entry alongside the `crates/*` glob. `omnifrons-shell` depended on `tauri`, `serde`, and `serde_json` only through part C — not `omnifrons-domain`, `omnifrons-app`, `omnifrons-supervisor`, or `omnifrons-adapters` (the last of which still exports nothing, see above). The ADR-0002 slice-1 spike ("supervisor to renderer streaming", [spike log](spike-log.md)) is the first typed command to need them: `omnifrons-shell` now depends on all three internal crates, plus `tracing`.

### Slice-1 spike additions: the demo harness and `ProcessOutput`

[The spike log](spike-log.md) records what this slice proves and defers in full; this section only updates the crate map and build surface it touches.

`omnifrons-app` gains `harness_catalog` (`HarnessKind` — a closed, two-variant enum, `DemoLines` and `DemoIgnoresSigterm` — and `HarnessRequest::new`, validating `rate_hz` (`1..=1000`) and `lines` (`1..=100_000`)) and a new port, `ProcessOutput` (`crates/omnifrons-app/src/process_output.rs`), independent of `ProcessSupervisor`: `subscribe(id)` hands back a one-shot `std::sync::mpsc::Receiver<OutputFrame>` per process, erroring `SupervisorError::AlreadySubscribed` (a new variant) on a second call for the same id. `OutputFrame`, `OutputStream` (`Stdout`/`Stderr`), and `FramePayload` (`Text { stream, text }` or `State(ProcessTerminalState)`) live in `omnifrons-domain/src/output.rs`, re-exported through `omnifrons-app`.

`TokioProcessSupervisor` is a cheap, `Clone`-able handle over shared state (`Arc<Inner>`), not a value that itself needs an external lock to be shared across threads: the `ProcessSupervisor`/`ProcessOutput` ports' `&mut self` methods are satisfied per clone (two clones are two independent local values), while the actual mutable state (`children`, `outputs`) is synchronized far more finely, inside `Inner`, than a single supervisor-wide lock ever could be. This is what lets a caller store the handle directly in shared state with no outer `Mutex` — see the shell's own managed-state change below — since wrapping the whole supervisor in one `Mutex` would otherwise serialize every command behind whichever one happened to be running a multi-second `stop` (`crates/omnifrons-supervisor/tests/concurrent_handles.rs`). `Inner`'s own `Drop` (not the handle's) performs the best-effort kill-on-drop cleanup and driver-thread shutdown, running only once the *last* handle sharing that `Inner` is dropped.

`omnifrons-supervisor` implements `ProcessOutput`: `spawn` now pipes every child's stdout and stderr and starts one reader task per stream on the supervisor's own Tokio runtime — which is why that runtime gained a dedicated background driver thread in this slice (`TokioProcessSupervisor::build`), since merely `enter()`ing a current-thread runtime around each synchronous call never actually polls a task spawned onto it. This current-thread-with-one-driver design is not incidental: `output_capture.rs`'s per-process `seq`/`dropped_before` bookkeeping (plain, unlocked atomics) is sound only because a process's stdout and stderr reader tasks can never truly run in parallel on it (`crates/omnifrons-supervisor/tests/runtime_drives_tasks.rs`'s `the_supervisors_runtime_is_current_thread_flavor` test stands guard on that). Each reader task frames decoded (lossy-UTF-8) text into `OutputFrame`s: `\r\n` is treated as a line end with the `\r` stripped, a final line with no trailing newline is still delivered once EOF is reached, and any line longer than **8 KiB** (`MAX_LINE_BYTES`) splits into consecutive frames at a UTF-8 character boundary — never mid-character — rather than growing one frame unbounded. Frames are delivered into a per-child bounded channel (capacity **1024**) via `try_send` only for text: a full channel drops the newest frame and counts it, surfaced as the next delivered frame's `dropped_before`, rather than ever blocking the reader. The one exception is the final `State` frame, carrying the confirmed terminal state once both reader tasks have finished and the process's reap is confirmed: it is guaranteed-delivered via a dedicated blocking-send thread rather than dropped alongside text when the channel is full, since it is the only signal a subscriber has that the process is truly done; the channel's sender is then dropped. An output-capture entry is removed entirely once both finalized (that terminal frame produced) and subscribed-out (a caller already took its receiver via `subscribe`) — an entry nobody ever subscribes to is retained indefinitely instead, so a late `subscribe` still finds an already-terminal process's buffered output.

A supervisor also caps its own bookkeeping: at most **16** concurrently `Running` children (`spawn`/`spawn_harness` refuse a 17th with the new `SupervisorError::TooManyProcesses`, mapped to `ShellError { code: "too-many-processes" }`, without ever spawning it), and at most **256** retained `Terminal` entries, oldest evicted first by termination order once that cap is exceeded. An evicted id then reports `UnknownProcess`/`None` from a later `stop`/`observe` — indistinguishable from an id this supervisor never spawned, and never a re-signal of a pid the OS may have since recycled, since an evicted entry was already confirmed reaped before it became eligible for eviction.

`TokioProcessSupervisor::with_demo_launcher(path)` and `spawn_harness(request)` turn a validated `HarnessRequest` into a real process without a program path or argument vector ever crossing IPC: the shell passes `tauri::process::current_binary(&env)` as the launcher; this crate's own tests pass `env!("CARGO_BIN_EXE_demo-harness")`. That launcher path is resolved once and cached for the supervisor's whole lifetime, with no identity re-probe before each launch — acceptable only because the "harness" it launches is this application's own binary, not a third-party executable a supply-chain compromise could swap out between launches ([threat model TM-001, HAR-3](threat-model.md); [spike log](spike-log.md) § What it defers). The `demo` module (`kind_arg`/`parse_kind`, `run`) and the always-built `demo-harness` binary (`src/bin/demo-harness.rs`) are the demo harness's actual logic and test-only launch target, shared with the shell's own hidden entry point below. `run` prints a leading `"ready"` stdout line — for both `HarnessKind`s, symmetrically — only once installed any `SIGTERM`-ignore handler it needs, giving a subscriber a genuine synchronization point to wait on before calling `stop`, rather than a fixed sleep and a guess at how long installation takes.

`omnifrons-shell` gains three typed commands next to `shell_health` — `harness_spawn` (async, takes a `tauri::ipc::Channel<HarnessFrame>` and starts a forwarder thread relaying every captured frame onto it), `harness_stop`, `harness_observe` — backed by a `TokioProcessSupervisor` managed directly, with **no outer `Mutex`**: each command clones the handle (`ipc::commands::with_supervisor`) before running its blocking supervisor call via `tauri::async_runtime::spawn_blocking`, so one command's multi-second `stop` never blocks an unrelated command behind a single shared lock. `harness_stop`'s `deadline_ms` is itself validated into `1..=30_000` before it ever reaches the supervisor, rejecting an out-of-range value with `ShellError { code: "invalid-request" }` rather than accepting an unbounded caller-supplied deadline. It also gains a hidden argv branch, `omnifrons-shell --demo-harness <kind> <rate_hz> <lines>`, parsed in `src/main.rs` before `tauri::Builder` runs, compiled only under the non-default `demo-harness` cargo feature (`cargo test -p omnifrons-shell --features demo-harness` exercises it; `tests/feature_gate.rs` asserts a binary built without the feature contains no `--demo-harness` string at all — `tests/feature_gate_present.rs` carries no such `cfg` gate itself, so it stays counted in every run's summary as a standing reminder that `feature_gate.rs` needs its own dedicated, feature-off CI step, below). `build.rs` still does not reference `AppManifest::commands`, and `capabilities/default.json` still grants exactly `core:default` — both asserted by `tests/config.rs` — so three new commands do not silently widen the capability surface.

Pinned exact versions (`workspace.dependencies`, resolved via `cargo info` at the time this crate was added): `tauri = "2.11.5"`, `tauri-build = "2.6.3"`, `serde = "1.0.229"`, `serde_json = "1.0.151"`. `omnifrons-shell` keeps Tauri's own default feature set (`wry`, `compression`, `common-controls-v6`, `dynamic-acl`, `x11`, `dbus`) — those are the runtime's own baseline capabilities, not optional plugins — and adds no Tauri plugin crate (no `tauri-plugin-fs`, `-shell`, `-http`, or `-dialog`).

`omnifrons-shell` registers exactly one typed command, `shell_health` (`src-tauri/src/lib.rs`), returning `{ "shell": "omnifrons-shell", "version": <crate version>, "containment": "unproven" }`. The pure logic lives in `health()` (`src-tauri/src/health.rs`), unit-tested without a Tauri runtime; `containment` stays `"unproven"` until VP-001 proves platform-specific process containment (adr/0002-desktop-technology-stack.md § Process supervision: Windows Job Object policy, Linux cgroup/process-group/watchdog behavior, and macOS process-group/watchdog behavior are all still unverified).

`src-tauri/capabilities/default.json` grants the main window exactly `core:default` and nothing else — no `fs`, `shell`, `http`, or `dialog` permission, matching invariant 4's "no generic shell and no unrestricted filesystem capability" (docs/target-architecture.md § Components and trust boundaries).

`src-tauri/tauri.conf.json`'s `app.security.csp` transcribes renderer-content-security.md § CSP baseline directive-for-directive, with one documented exception: the baseline sets `connect-src` to `'none'`, but Tauri's own IPC bridge rides `ipc:` (the custom-protocol transport used on Linux and macOS) and `http://ipc.localhost` (the transport Windows WebView2 requires in place of a custom scheme), so `connect-src` here is `"ipc: http://ipc.localhost"` instead. This is the platform-bridge exception renderer-content-security.md § CSP baseline itself anticipates ("Where a platform's bridge implementation requires a custom protocol handler to carry that traffic, the protocol is added to `connect-src` explicitly, documented in this section, and verified under VP-001 — never left as an implicit, undocumented exception to the baseline above"); it is a VP-001 input, not a silent loosening, and every other directive (`default-src`, `script-src`, `style-src`, `img-src`, `media-src`, `font-src`, `manifest-src`, `frame-src`, `object-src`, `base-uri`, `form-action`, `worker-src`) is transcribed unchanged. Tauri appends its own nonces and hashes to bundled scripts and styles at compile time, so `script-src 'self'` and `style-src 'self'` need no `'unsafe-inline'` or manually-managed nonce. `src-tauri/tests/config.rs` asserts this transcription and the capability's scope so a future edit cannot silently widen either.

`tauri.conf.json`'s `identifier` is `"dev.omnifrons.app"` — a placeholder. The final identifier is an owner decision tied to product naming (see this page's Name status and ADR-0002's), not a Rust-toolchain concern; it is free to change before ADR-0002's acceptance gate closes.

`src-tauri/icons/` holds placeholder app icons only (a solid, flat color, no real artwork): `32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.png`, `icon.ico`, and `icon.icns`, generated by `src-tauri/icons/generate-placeholder-icons.py` (stdlib-only: hand-rolled PNG encoding via `zlib`, PNG-in-ICO framing, and PNG-backed ICNS `ic07`/`ic11`/`ic13` chunks — no Pillow or ImageMagick required). They exist only so `tauri.conf.json`'s `bundle.icon` list points at files that exist and decode cleanly for `cargo check`/`cargo build`/`cargo test`; real app art is a separate, later concern.

Build and test `omnifrons-shell` on its own with:

```sh
cargo check -p omnifrons-shell
cargo test -p omnifrons-shell
```

### Slice-2 spike additions: executable identity and approval

[The spike log](spike-log.md) § Slice 2 records what this slice proves and defers in full; this section only updates the crate map and build surface it touches.

`omnifrons-domain` gains `executable` (`crates/omnifrons-domain/src/executable.rs`): `Sha256Digest`, `PlatformEvidence`, `ExecutableIdentity` (hand-written `PartialEq` comparing canonical path, size, and digest only — `modified_at` and platform evidence are informational), `ProbeOutcome`, `ApprovalId`, `DeviceLocalUser` (an opaque, no-name approver marker), `ApprovalStatus`, `ApprovalRecord`, `DenialReason`, `LaunchDecision`, and `PublicToken` (a `DenialReason`'s public-facing reduction, via `DenialReason::public_token()` — closed to `Untrusted`/`Uncertain`/`Failed`, deliberately with no "done"/"trusted" variant, since every `DenialReason` is definitionally a denial).

`omnifrons-app` gains three new ports (`src/{executable_prober,approval_store,clock}.rs`) and `LaunchGate` (`src/launch_gate.rs`): `ExecutableProber::probe(&self, candidate: &Path) -> ProbeOutcome`; `ApprovalStore { list, record, revoke, find_active }` over a closed `ApprovalStoreError { Unreadable, Corrupt, WriteFailed }`; `Clock::now()`. `LaunchGate<P, S, C>` (generic over those three ports) is the application-layer decision point: `decide(&mut self, approval_id) -> LaunchDecision` re-probes the recorded canonical path fresh on every call — never a cached identity — comparing canonical path, digest/size, and status in that order, and fails closed as `Unapproved` if the approval store itself cannot even be read; `approve_candidate`/`revoke` write through to the store. Fakes behind the existing `contract-tests` cargo feature (`src/contract/approval_store.rs`): `FakeProber` (a scripted, `Clone`-able spy counting its own calls), `InMemoryApprovalStore`, `FixedClock`, and a reusable `approval_store_contract` test both `InMemoryApprovalStore` (`omnifrons-app`'s own tests) and `JsonlApprovalStore` (`omnifrons-adapters`'s tests, via the same dev-dependency pattern `omnifrons-supervisor` already established for the `ProcessSupervisor` contract) run against themselves. `HarnessKind` gains a third variant, `Approved(ApprovalId)` — unlike the two demo kinds, it never flows through `HarnessRequest`/`spawn_harness`'s argv-encoding path.

`omnifrons-adapters` stops being an empty placeholder for the first time: `FsExecutableProber` (`src/fs_prober.rs`) implements `ExecutableProber` against the real filesystem — canonicalize, confirm the canonical path is a regular, executable file (unix: any execute permission bit; windows: an extension allowlist, documented as provisional) within a 512 MiB cap checked from metadata alone before ever opening the file, then stream-hash in 64 KiB chunks (`sha2`) — and additionally exposes `open_for_exec` (Linux only) for the supervisor's fd-exec launch path. `JsonlApprovalStore` (`src/jsonl_approval_store.rs`) implements `ApprovalStore` as one append-only `approvals.jsonl` file (created with unix mode `0o600`; a revocation is a new line referencing an earlier approval id, never an edit of it; a truncated or malformed line fails the whole read as `Corrupt`, never a silent partial result), serialized through an adapters-local record shape (`serde`/`serde_json`) that maps to and from the domain types. This is why the crate's `[dependencies]` table grows from `{omnifrons-domain, omnifrons-app}` to exactly `{omnifrons-domain, omnifrons-app, sha2, serde, serde_json}` — `tests/deps.rs` still fails the build the moment a Tokio or Tauri dependency appears, and now also fails if this exact five-crate set drifts.

`omnifrons-supervisor`'s own `[dependencies]` table is unchanged by this slice. It gains `TokioProcessSupervisor::spawn_approved(&mut self, canonical_path, opened: Option<File>)`, launching with no arguments: on Linux, given an already-open file handle, it execs `/proc/self/fd/0` (the handle passed as this command's `stdin`, so `Command`'s own fork/exec machinery clears close-on-exec on it via `dup2` — a duplicate is never close-on-exec regardless of the original, which is what lets this work uniformly for both a direct binary and a `#!`-interpreted script with no `unsafe` code and no new dependency) rather than the canonical path by name, so a file replaced after that handle was opened still executes with its original content; on macOS and Windows it spawns by canonical path directly, with that gap left open. `open_for_exec` itself lives in `omnifrons-adapters` (above), not here — the shell is what calls it and threads the result into `spawn_approved`, which is why this crate needed no new dependency to gain the capability.

`omnifrons-shell` gains `omnifrons-adapters` and `tauri-plugin-dialog` (pinned exactly: `tauri-plugin-dialog = "2.7.3"`, resolved via `cargo info` at the time this crate was added, same convention as the existing `tauri`/`tauri-build`/`serde`/`serde_json` pins) as dependencies, and registers `tauri_plugin_dialog::init()` next to `tauri::Builder::default()`. Managed state grows a second entry, `ExecutableState` (`src/executable_state.rs`): a `Mutex`-guarded `LaunchGate<FsExecutableProber, JsonlApprovalStore, SystemClock>` (`SystemClock` is a trivial `Clock` wrapping `SystemTime::now()`) plus a bounded (32-entry, oldest-evicted) table of probed-but-not-yet-approved candidates. The approval store opens at `app.path().app_local_data_dir()` joined with `approvals.jsonl`, logged at debug only. Four new typed commands — `executable_pick_and_probe`, `executable_approve`, `executable_revoke`, `approvals_list` — and `harness_spawn`'s `kind` parameter becomes an internally tagged enum (`{"type": "demo-lines", "rateHz", "lines"}` / `{"type": "demo-ignores-sigterm", ...}` / `{"type": "approved", "approvalId"}`, each variant bundling exactly the parameters it needs) rather than a flat `kind` string plus separate `rateHz`/`lines` — a flat shape would let a caller submit a meaningless combination (e.g. `approved` with a `rateHz`) that would then need extra validation to reject after the fact. Every new blocking operation (the file picker, probing, gate decisions, store reads/writes) runs via `tauri::async_runtime::spawn_blocking`, matching the existing `harness_spawn`/`harness_stop`/`harness_observe` pattern. Nine new `ShellErrorCode` values join the existing five, each a fixed catalogue message with no `/`; `changed-since-approval` is the one case carrying a structured `detail` field (both digests as 8-character short-hex prefixes, never a full digest or a path). `capabilities/default.json` stays exactly `core:default` — calling `tauri_plugin_dialog::DialogExt::dialog()` from inside a shell command's own Rust body is a direct method call, never an IPC invocation of `plugin:dialog|open` from the webview, so Tauri's capability/ACL enforcement (which gates IPC-invoked plugin commands crossing the webview boundary) never applies to it; `src-tauri/tests/config.rs`'s existing `default_capability_grants_only_core_default` test is unchanged and still passes, standing proof this addition did not silently widen the capability surface.

### Slice-2 review-fix pass

A review pass on the slice-2 spike (above) found the stat-by-path-then-open-by-path prober sequence and the stdin-carries-the-executable launch trick both left a real TOCTOU window; this section records the fix. [The spike log](spike-log.md) § Slice 2 is updated in place for the same reason and stays the fuller account.

`omnifrons-domain`'s `executable` module is unaffected in shape (`ProbeOutcome`, `LaunchDecision`, and every other type there are unchanged): the handle a probe now carries has no business in a framework-independent domain type, so it lives one layer up instead.

`omnifrons-app`'s `ExecutableProber::probe(&self, candidate: &Path) -> ProbeOutcome` now names an app-level `ProbeOutcome` (`src/executable_prober.rs`, not the domain one), whose `Identity` variant carries a `ProbedExecutable { identity: ExecutableIdentity, handle: ExecHandle }` rather than a bare identity — `ExecHandle::File(std::fs::File)` on every platform, plus `ExecHandle::SealedMemory(std::fs::File)` on Linux. `LaunchGate::decide` returns a new `GateDecision { Allowed { approval_id, executable: ProbedExecutable }, Denied(DenialReason) }` instead of the domain `LaunchDecision`, so a caller receives the exact handle its own re-probe just produced, never a reason to re-open the path a second time. `ApprovalStoreError` gains a fourth variant, `Duplicate` (a derived id already on record). `HarnessRequest::new` now rejects `HarnessKind::Approved` outright with a new `InvalidRequest::KindNotDemo`, since that kind never flows through this argv-encoding, rate/lines-bounded shape at all.

`omnifrons-adapters` gains a unix-only dependency, `nix` (`default-features = false`, features `fs` and `user`; verified against the vendored 0.31.3 source that `fs` alone gates `OFlag::O_NOFOLLOW`, `sys::memfd::{memfd_create, MFdFlags}`, and `fcntl`'s `FcntlArg::F_ADD_SEALS`/`SealFlag` — 0.31.3 has no separate `fcntl` cargo feature; `user` gates `nix::unistd::Uid::effective`/`is_root`, used only by this crate's own tests). `FsExecutableProber` now canonicalizes, opens the canonical path *exactly once* (unix: `O_NOFOLLOW` via `OpenOptionsExt::custom_flags`, refusing a symlink dropped at that exact path after canonicalization; not available on Windows, a documented limitation), and runs the regular-file/executable-bit/size-cap checks against that one open handle's own `fstat` rather than a separate `stat`/`lstat` by path. On Linux, content is hashed *while copying* into a fresh `memfd` (`MFD_CLOEXEC | MFD_ALLOW_SEALING`), then sealed (`F_SEAL_SHRINK | F_SEAL_GROW | F_SEAL_WRITE | F_SEAL_SEAL`) before being returned as `ExecHandle::SealedMemory` — the sealed content is exactly the hashed bytes, immutable from that point on, including against this process itself. `open_for_exec` is removed entirely: the handle a caller launches is the one `probe` itself already opened and hashed from. The Windows executable-extension allowlist is extracted into a pure `is_windows_executable_extension(&str) -> bool`, unit-tested on every platform. `JsonlApprovalStore` gains a `schema: u32` field on every JSONL line (any value but the one this version writes fails the whole read as `Corrupt`), calls `sync_data()` before `append_line` returns `Ok`, and derives each `ApprovalId` from `sha256(domain ++ canonical_path ++ sha256 digest ++ approved_at nanoseconds)` rather than counting existing records — `record` rejects a derived id already on file with `ApprovalStoreError::Duplicate`.

`omnifrons-supervisor`'s existing `nix` dependency gains the `fs` feature (still unix-only, no new dependency), needed for `fcntl`. `TokioProcessSupervisor::spawn_approved` is now `spawn_approved(&mut self, handle: ExecHandle, display_path: PathBuf)`: given `ExecHandle::SealedMemory` (Linux), it clears close-on-exec on the memfd (`fcntl(F_SETFD, FdFlag::empty())`) and execs it via `/proc/self/fd/<n>` with no arguments and `stdin` always `Stdio::null()` — never the executable's own bytes, unlike the previous stdin-carries-the-file trick this replaces; the fd remains open in the child by design (needed for a `#!`-interpreted script's own re-open of that same `/proc/self/fd/<n>` path). Given `ExecHandle::File` (macOS, Windows, or a Linux fallback), it spawns by `display_path` directly, with only inode identity during hashing guaranteed and the window to exec left open, exactly as before. `demo::kind_arg` now returns `Result<&'static str, NotADemoKind>` instead of panicking on `HarnessKind::Approved` — structurally unreachable now that `HarnessRequest::new` rejects that kind up front, but total rather than panicking regardless.

`omnifrons-shell`'s `harness_spawn` for the `approved` kind no longer makes a second approval-store round trip to look up the canonical path once `LaunchGate::decide` reports `Allowed`: the `GateDecision::Allowed` variant already carries the `ProbedExecutable` that decision's own re-probe produced, threaded straight into `spawn_approved`. `executable_pick_and_probe` keeps only the identity in its candidate table; the handle a probe returns is dropped there, since approval re-probes at launch time regardless. `HarnessKindDto` gains `#[serde(deny_unknown_fields)]`, so an extra field on any tagged variant is now rejected rather than silently ignored.

## Build and test commands

From the repository root, with pnpm installed:

```sh
pnpm install --frozen-lockfile   # install every workspace package
pnpm -r lint                     # lint every workspace package
pnpm -r test                     # run every workspace package's tests
pnpm -r build                    # build every workspace package
```

`rust-toolchain.toml` now exists, so the equivalent Rust commands run today and join CI (wired in ci.yml and tauri-build.yml, previously guarded on that file's existence):

```sh
rustup show
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --all-features
cargo tree -p omnifrons-domain               # must show only thiserror
cargo tree -p omnifrons-app -e normal        # must show no tokio
```

`--all-features` is what enables `omnifrons-app`'s `contract-tests` feature, which in turn is what makes `omnifrons-supervisor`'s contract test (`tests/contract.rs`) and `omnifrons-app`'s own fake-backed test binaries compile and run. Seven of `omnifrons-app`'s test files are `#![cfg(feature = "contract-tests")]` in their entirety and build with **zero tests** without the feature: `tests/approval_store_contract.rs`, `tests/contract_harness_adapter.rs`, `tests/contract_process_supervisor.rs`, `tests/launch_gate.rs`, `tests/content_hasher.rs`, `tests/publication.rs`, and `tests/publication_contracts.rs` (the last three are the slice-5b publication suite). Run them with `cargo test -p omnifrons-app --all-features` (or `--features contract-tests`), which is what CI's `--all-features` step does; a bare `cargo test -p omnifrons-app --test publication` reports `0 passed` and proves nothing. It also enables `omnifrons-shell`'s `demo-harness` feature, compiling in the hidden `--demo-harness` argv branch; `cargo test -p omnifrons-shell --features demo-harness` runs that configuration on its own, and `tests/feature_gate.rs` runs only without it (`#![cfg(not(feature = "demo-harness"))]`), asserting the literal `--demo-harness` string is absent from a binary built that way.

## Toolchain pins and VP-001

The pins recorded here — package manager, Node runtime, and renderer toolchain versions — are candidate values for the "Rust, Node, and toolchain versions" field VP-001 records once per pinned baseline, at first execution (desktop-stack-verification-plan.md § Pinned baselines). This page names what is installed; it is not itself VP-001 evidence, and VP-001 stays the sole authority for the exact-OS-build, test-date, and evidence-artifact fields a baseline row requires (desktop-stack-verification-plan.md § Evidence record).

Current pins:

- Package manager: pnpm, pinned exactly via `packageManager` and `devEngines.packageManager` in the root `package.json`, enforced by `engineStrict` in `pnpm-workspace.yaml`. - Renderer toolchain: React 19, TypeScript, Vite, Vitest with `jsdom`, `@testing-library/react`, and ESLint, all pinned in `renderer/package.json`.
- Rust toolchain: pinned via `rust-toolchain.toml` (`channel = "1.98.1"`, `components = ["rustfmt", "clippy"]`, `profile = "minimal"`); the workspace's `[workspace.package]` restates the same version as `rust-version` and pins `edition = "2024"`; `rustfmt.toml` and `clippy.toml` pin `edition = "2024"` and `msrv = "1.98.1"` respectively for their own tools.

## CI overview

Four workflows live in `.github/workflows/`, each with `permissions: read-all` (or narrower) at the top level and a concurrency group keyed on `${{ github.workflow }}-${{ github.ref }}` with `cancel-in-progress: true`, and each job carries a `timeout-minutes` bound. `ci.yml` and `tauri-build.yml` share their Rust and Node/pnpm setup through the `.github/actions/setup-toolchain` composite action, so the two workflows cannot drift on how each toolchain is installed:

- **ci.yml** — `build-test` (45-minute timeout, widened from 30 once the shell started compiling Tauri/wry/WebKit bindings on all three runners), on push to `main` and on pull request, across an `ubuntu-latest` / `macos-latest` / `windows-latest` matrix. Runs `pnpm -r lint`, `pnpm -r test`, and `pnpm -r build`; the Rust steps (`cargo fmt`, `cargo clippy`, `cargo test`) were guarded on `rust-toolchain.toml` existing and now run, since part B added that file. Immediately after the `--all-features` `cargo test` step, a dedicated `cargo test -p omnifrons-shell --test feature_gate` step runs with **neither** `--all-features` nor `--features`: `tests/feature_gate.rs` is entirely `#![cfg(not(feature = "demo-harness"))]`, so the `--all-features` step alone always reports zero tests for that file and could never catch a regression that made the `demo-harness` feature default-on. `tauri-build.yml` carries the identical step, for the same reason. As of part C it also passes `linux-prereqs: 'true'` to `setup-toolchain`, installing `libwebkit2gtk-4.1-dev` and the other Tauri Linux build prerequisites on the `ubuntu-latest` leg before `cargo test --workspace` links `omnifrons-shell` against WebKitGTK; the input is a no-op on `macos-latest` and `windows-latest` (their WebViews, WKWebView and WebView2, ship with the OS).
- **gitleaks.yml** — `gitleaks` (10-minute timeout), scanning the full history for committed secrets; `permissions: read-all` deliberately omits `pull-requests: write`, so findings surface only in the job log, not as inline PR annotations. (Renamed from `secrets.yml`: that filename matched the maintainer's global `*secret*` gitignore rule and could never be tracked by Git.)
- **docs.yml** — `docs-links` (10-minute timeout), checking every relative link and anchor (`--include-fragments`) under `docs/**/*.md`, `README.md`, `CONTRIBUTING.md`, and `SECURITY.md` in offline mode.
- **tauri-build.yml** — `build-test` (60-minute timeout), on `workflow_dispatch` and a daily schedule, same three-OS matrix; the Tauri packaging step is guarded on both `rust-toolchain.toml` and `src-tauri/tauri.conf.json` existing. Both now exist as of part C, so this step is live; it also already passed `linux-prereqs: 'true'` and `extra-apt-packages: patchelf` to `setup-toolchain` (patchelf is needed for AppImage bundling, not for `ci.yml`'s plain `cargo test`). This step's packaged build has not been run locally — VP-001, not this page, owns that evidence. No signing identity is configured for `tauri-action` today, so the packaged build is expected to produce unsigned artifacts per OS until UTA-001's signing identities exist; this is expected, not a defect, but should be confirmed by the first `workflow_dispatch` run rather than assumed.

Required check names a future branch-protection rule names against these workflows:

- `build-test (ubuntu-latest)`
- `build-test (macos-latest)`
- `build-test (windows-latest)`
- `gitleaks`
- `docs-links`

## Hygiene

`.editorconfig` fixes UTF-8, LF line endings, a final newline, trimmed trailing whitespace, and two-space indentation repository-wide, with a four-space exception for `*.rs` and no trailing-whitespace trimming for `*.md` (Markdown's own trailing-space line-break convention). `.gitignore` excludes build output (`node_modules/`, `renderer/dist/`, `.vite/`, `*.tsbuildinfo`, `coverage/`, `.pnpm-store/`), Rust/Tauri build artifacts (`/target`, `**/target`, `src-tauri/target/`, `src-tauri/gen/`, `src-tauri/WixTools/`) — the last three were staged ahead of part C and now apply to the real crate; `src-tauri/icons/` is deliberately not ignored, since its (placeholder) icons are `tauri.conf.json`'s `bundle.icon` inputs, not build output — and local secrets and keys (`.env`, `.env.*` — with a standing exception for a future `.env.example` — `*.pem`, `*.key`, `*.p12`, `*.pfx`). `Cargo.lock` is committed, not ignored: this workspace produces binaries/libraries other crates and CI depend on building reproducibly, not a library meant to float on its dependents' resolution. `CODEOWNERS`, `CONTRIBUTING.md`, and `SECURITY.md` at the repository root record ownership, contribution, and disclosure process ahead of any external contribution.
